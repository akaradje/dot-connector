# 🔗 The Dot-Connector AI — v4 "The Self-Forge"

เครื่องมือสร้างนวัตกรรมตามปรัชญา "Connecting the Dots" ของ Steve Jobs —
เก็บ "จุดความรู้" จากชีวิตจริงโดยอัตโนมัติ → AI ลากเส้นเชื่อมข้ามโดเมนเองเบื้องหลัง →
**เด้งแจ้งเตือน Eureka บน Windows โดยไม่ต้องเปิดแอป** →
พิสูจน์ความใหม่กับโลกจริงด้วยการค้นเว็บ → ได้ต้นแบบที่รันได้จริง →
**และเมื่อชนเพดานของตัวเอง มันเขียนซอร์สโค้ดของตัวเองใหม่เพื่อทำลายเพดานนั้น** →
**และเมื่อคุณไม่ว่าง มันออกไปหาความรู้ใหม่มาเติมคลังเอง (Layer 07 · The Scout)** →
**และตั้งแต่ Layer 06.8 มันเลิกตัดสินตัวเองที่วินาทีที่โค้ดเขียนเสร็จ: อีกไม่กี่วันให้หลัง
บันทึกการใช้งานจริงจะบอกว่าความสามารถที่มันเพิ่งสร้าง มีใครเรียกใช้จริงหรือไม่ — และคำตอบนั้นเปลี่ยนว่ามันจะสร้างอะไรต่อ**

> v2 "HexKern Memory" ออกแบบโดยตัวเครื่องมือเอง · v3 มองย้อนกลับแทนคุณตลอดเวลา ·
> **v4 หันเครื่องมือเข้าหาตัวเอง**: จุดความรู้ชุดสุดท้ายที่ยังไม่เคยถูกเชื่อม คือซอร์สโค้ดของตัวมันเอง
> ขับเคลื่อนด้วย **Claude Opus 5** ทุกชั้น (ชั้นหลอมตัวเองใช้ context 1M เพื่ออ่านตัวเองได้ทั้งระบบในครั้งเดียว)

## สถาปัตยกรรม

| ชั้น | แนวคิด | ในแอปนี้ |
|---|---|---|
| Layer 00 | **The Collector** | โยนไฟล์ .txt/.md ลง `inbox/` หรือวางความคิดดิบในหน้าเว็บ — AI สกัดเป็นจุดความรู้เอง (แยกโดเมนให้เอง, กันจุดซ้ำ) |
| Layer 01 | Dot Repository + **HexKern Memory** | `data/dots.json` — ทุกจุดมีดัชนีความหายาก (rarity) และ **คะแนนคุณค่าจากผลลัพธ์จริง (value_score)** ลำดับความสนใจคือ `attention_score` ที่รวมทั้งสองอย่าง จุดที่ไม่เคยถูกเชื่อมจะ "เรืองแสง" ส่วนจุดที่เคยพาไปทางตันซ้ำ ๆ จะจมลง |
| Layer 02 | Pattern Recognition | Claude สแกนจุดทั้งหมดหา structural isomorphism (ให้น้ำหนักจุดหายากมากกว่า) |
| Layer 03 | Connection + **Serendipity Revival** | จุดที่ถูกทิ้งเกิน 14 วันขึ้นแบนเนอร์ "กำลังจะตายจากคลัง" กดปลุกเพื่อบังคับเชื่อมมันเข้ากับจุดใหม่ (กลไก Loss Aversion) |
| Layer 04 | Combinatorial Innovation + **Eureka-to-Evidence** | ทุกไอเดียกด "พิสูจน์" ได้ — Evidence Agent ค้นเว็บจริงเช็กความใหม่ระดับโลก ประเมินความเสี่ยง ออกแบบการทดลอง และเขียนโค้ดต้นแบบลง `lab/` |
| Layer 04.5 | **The Return Path** (เส้นตอบกลับ) | ทุกการเชื่อมมีช่องบันทึก "ผลลัพธ์จริง" (คะแนน 1-5 + เอาไปทำแล้วเกิดอะไร) ผลลัพธ์นั้นรวมกับ verdict ของ Evidence Agent กลายเป็น **คะแนนคุณค่าของจุด** ที่ใช้จัดลำดับความสนใจแทน rarity ล้วน และกลายเป็น **บทเรียน** ที่ป้อนเข้าพรอมป์ตรอบถัดไปแทนบัญชีดำรายชื่อ — การเชื่อมครั้งที่ 100 จึงเก่งกว่าครั้งแรกได้ |
| Layer 05 | **Serendipity Daemon** | ลูปเบื้องหลังตรวจทุก 30 นาที: เก็บเกี่ยว inbox → ถ้ามีจุดใหม่หรือจุดเก่าครบกำหนด → เชื่อมจุดเอง → **เด้ง Windows toast แจ้ง Eureka** |
| Layer 06 | **The Self-Forge** | ระบบอ่านซอร์สโค้ดของตัวเอง → ตั้งชื่อ "ขอบเขต" ที่ขังตัวเองไว้ (`data/limits.json`) → **เขียนโค้ดตัวเองใหม่เพื่อทำลายขอบเขตนั้นจริง ๆ** → **พร้อมเขียน "ไฟล์พิสูจน์" ที่รันได้จริงลง `selftest/` ซึ่งต้องผ่านกับโค้ดใหม่และตกกับโค้ดเดิม** + regression ทุก endpoint เดิม → ไม่ผ่านย้อนกลับอัตโนมัติ → ผ่านแล้วบันทึกเป็น "จุดความรู้" ใหม่กลับเข้าคลังของตัวเอง |
| Layer 06.5 | **Scar Tissue** (แผลเป็น) | รอบที่ล้มเหลวไม่ถูกลบทิ้งพร้อมบทเรียนอีกต่อไป: โค้ดที่ตกถูกเก็บไว้ที่ `evolution/backups/<evo-id>/attempted/` และรอบถัดไปที่ชนกำแพงเดิม **ถูกป้อนประวัติความล้มเหลวทั้งหมดเข้าพรอมป์ต** พร้อมคำสั่งห้ามใช้วิธีเดิมซ้ำ · และ **เพดาน 3 ครั้งตายตัวกลายเป็นเพดานที่ขยับได้** (สูงสุด 6) — [รายละเอียด](#-แผลเป็น-รอบที่ล้มเหลวถูกส่งต่อ-ไม่ใช่ถูกลบ) |
| Layer 06.6 | **The Consolidator** (ทิศทางที่สอง) | เดิมรอบวิวัฒนาการผ่านได้ทางเดียว เพราะไฟล์พิสูจน์ต้อง **ตกกับโค้ดเดิม** — การรวบโค้ดซ้ำหรือลบของที่ไม่มีใครใช้จึง **พิสูจน์ไม่ได้โดยนิยาม** ระบบจึงมีแต่ใหญ่ขึ้น ตอนนี้มี **รอบชนิดที่สอง** ที่ฟังก์ชันความเหมาะสมกลับด้าน: ชุดทดสอบสะสมต้อง **ผ่านทั้งก่อนและหลัง** แล้ววัดด้วย **ตัวเลขขนาดที่ลดลง** โดยยังบังคับ regression sweep เต็มรูปแบบ · และ `REGRESSION_ENDPOINTS` ถอดเส้นทางที่ถูกเรียก 0 ครั้งออกได้ (มีทะเบียนกำกับ ย้อนกลับได้) — [รายละเอียด](#-layer-066--รอบยุบรวม-ระบบที่ลดขนาดตัวเองได้โดยพิสูจน์ได้) |
| Layer 06.7 | **The Closed Loop** (ผู้เขียนอยู่ในห้องตอนตรวจข้อสอบ) | เดิมรอบหลอมตัวเองเป็นการ **ยิงนัดเดียวจบ**: โมเดลได้แค่ Read/Edit/Write/Glob/Grep เขียนเสร็จโปรเซสก็ตาย แล้วด่านทั้งห้าเพิ่งถูกรัน — `runProof()` พิมพ์ stdout จริงของไฟล์พิสูจน์ทิ้งไว้ใน `checks.capability_detail` ที่รอบนั้นไม่มีวันได้อ่าน ความรู้ที่ตัดสินเป็นตายมีครบตั้งแต่นาทีที่ 3 แต่ไปถึงมือคนที่ยังแก้ได้เร็วที่สุดคือรอบถัดไป ตอนนี้รอบเป็น **ลูปปิด**: ตรวจทันทีหลังโมเดลตอบ → ตกที่ด่านไหน ป้อน **stdout จริง** กลับเข้า **เซสชันเดิม** เป็นเทิร์นถัดไป (สูงสุด `FORGE_MAX_TURNS`) → ย้อนกลับก็ต่อเมื่อเทิร์นหมด · และโมเดลได้ `Bash(node --check:*)` ไว้ตรวจ syntax เองในเทิร์นของตัวเอง — [รายละเอียด](#-layer-067--ลูปปิด-ผลตรวจที่ไปถึงคนที่ยังแก้ได้ทัน) |
| Layer 06.8 | **The Adoption Ledger** (เส้นตอบกลับของตัวระบบเอง) | ทุกด่านของรอบหลอมตัวเองตัดสิน **ที่วินาทีที่โค้ดเขียนเสร็จ**: ไฟล์พิสูจน์ผ่าน ตัวเลขขนาดลด endpoint ตอบ 200 ไม่มีด่านไหนถามว่าความสามารถที่เพิ่มมาเมื่อยี่สิบรอบก่อน **มีใครเรียกใช้จริงหรือไม่** ทั้งที่ `evolution/endpoint-usage.json` บันทึกคำตอบไว้ครบตั้งแต่ Layer 06.6 — แต่มันถูกอ่านเป็นแค่ "ใบอนุญาตให้ถอดเส้นทาง" ไม่ใช่สัญญาณคุณค่า ระบบจึงสะสมความสามารถที่ถูกเรียก 0 ครั้งได้ไม่จำกัดและนับทุกครั้งว่าเป็นความคืบหน้า ตอนนี้ (1) ทุกรอบขยายต้อง **ประกาศเส้นทางที่ความสามารถจะถูกใช้ผ่าน** (ด่าน `declared_usage`) (2) อีก `ADOPTION_DAYS` วันให้หลัง บันทึกการใช้งานจริงให้คะแนนรอบนั้นด้วย **สูตรเดียวกับ `connectionSignal()`** — ก่อนครบกำหนด ความเงียบให้คะแนน `null` ไม่ใช่ติดลบ (3) รอบที่ได้ 0 hit ติดกันถูก **เสนอเป็นเป้าหมายของรอบยุบรวมเองอัตโนมัติ** และคะแนนนี้ถูกป้อนกลับเข้า `selectTarget()` — [รายละเอียด](#-layer-068--the-adoption-ledger-ด่านที่มาทีหลัง) |
| Layer 08 | **The Distiller** (คลังเลิกโตทางเดียว) | Layer 06.6 ให้ทิศทางที่สองกับ *โค้ด* แต่ฝั่ง *ความรู้* กำแพงรูปทรงเดียวกันยังยืนครบ: ทุกทางเข้าของจุดเป็นการเพิ่มล้วน ๆ ทางออกมีทางเดียวคือมนุษย์กด DELETE และ `buildConnectPrompt()` ยัด `d.content` ของทุกจุดโดยไม่มีเพดาน — จุดที่ระบบเรียกว่า "ถูกลืม" ยังถูกอ่านครบทุกตัวอักษร พรอมป์ตจึงยาวขึ้นเชิงเส้นตามจำนวนจุดตลอดกาล ตอนนี้ (1) พรอมป์ตมี **เพดาน**: หัวแสดงเต็ม หางย่อเหลือดัชนีบรรทัดเดียว — นี่คือการลืมจริงครั้งแรกของระบบ (2) มี **รอบยุบรวมความรู้** ที่รวบจุดซ้ำซ้อนเป็นจุดหลักการเดียว ผ่านก็ต่อเมื่อการเชื่อมที่เคยได้ผลจริงยังอธิบายได้ · จุดที่ proven ไม่หาย · พรอมป์ตสั้นลงจริง (3) จุดเดิมถูก **เก็บไว้ทั้งดวงใน `data/knowledge.json`** และย้อนกลับได้เหมือน evolution ledger — [รายละเอียด](#-layer-08--the-distiller-คลังที่ยุบรวมตัวเองได้โดยพิสูจน์ได้) |
| Layer 07 | **The Scout** (ความรู้เลิกเข้าทางเดียว) | เดิมจุดใหม่เกิดได้สามทางเท่านั้น: คนพิมพ์ · คนโยนไฟล์ลง `inbox/` · ระบบทำลายกำแพงตัวเองสำเร็จ ทั้งที่ Evidence Agent ค้นเว็บจริงทุกครั้งแล้วทิ้งสิ่งที่เจอ ตอนนี้ (1) `similar_found` ทุกชิ้นกลายเป็นจุดจริง ติดป้าย `origin: scout:evidence` (2) ระบบอ่านสำมะโนโดเมนของตัวเอง เขียนคำค้นเอง แล้วออกไป WebSearch เติมช่องว่าง (3) จุดที่ระบบหามาเอง **กดปฏิเสธได้** และคำปฏิเสธถูกจำไว้ถาวร — [รายละเอียด](#layer-07--the-scout-ความรู้ที่เดินเข้ามาเอง) |

## 📈 Layer 06.8 — The Adoption Ledger: ด่านที่มาทีหลัง

ทุกด่านที่ระบบนี้เคยมี ตัดสินภายในนาทีเดียวกับที่โค้ดเขียนเสร็จ:

```
ด่านที่มีอยู่ทั้งหมด        ตัดสินเมื่อ                    คำถามที่มันถาม
proof_written · syntax      โค้ดเพิ่งถูกเขียน              "มันบูตได้ไหม เขียนหลักฐานไหม"
capability · differential   นาทีที่ 3 ของรอบ               "โค้ดใหม่ทำได้ และโค้ดเดิมทำไม่ได้ ใช่ไหม"
preservation · shrink       นาทีที่ 10 ของรอบ              "เท่าเดิมเป๊ะและเล็กลงไหม"
regression                  ก่อนรอบจบ                      "ของเดิมยังตอบ 200 ครบไหม"
──────────────────────────────────────────────────────────────────────────────────
ไม่มีด่านไหน                —                              "ของที่สร้างเมื่อยี่สิบรอบก่อน มีใครเรียกไหม"
```

คำตอบมีอยู่บนดิสก์มาตลอด: `evolution/endpoint-usage.json` นับทุกคำขอที่เข้า `/api/*` มาตั้งแต่ Layer 06.6
แต่มันถูกอ่านที่เดียวคือ `retireEndpoint()` / `planRetirements()` — เป็น **ใบอนุญาตให้ถอดเส้นทาง** ไม่ใช่สัญญาณคุณค่า
`proveEvolution()` และ `consolidationVerdict()` ไม่เรียก `loadUsage()` เลยแม้แต่ครั้งเดียว
ผลคือระบบสะสมความสามารถที่ถูกเรียก **0 ครั้ง** ได้ไม่จำกัด และนับทุกครั้งว่าเป็นความคืบหน้า
Layer 04.5 สร้างเส้นตอบกลับให้ "ไอเดีย" ตั้งแต่แรก — แต่ "ตัวระบบเอง" ไม่เคยมีเส้นนั้น

**ยาขนานเดียวกัน ชี้กลับมาที่ตัวเอง** — และเป็นสูตรเดียวกันจริง ๆ ไม่ใช่แค่คล้ายกัน:

```
ไอเดียหนึ่งอัน   Evidence verdict + ผู้ใช้เอาไปทำอะไร   ┐
รอบหนึ่งรอบ      มีใครเรียกเส้นทางที่มันประกาศไว้ไหม     ┴→ weightedSignal() → [−1, +1]
```

`connectionSignal()` ถูกรีแฟกเตอร์ให้เรียก `weightedSignal()` ตัวเดียวกับที่ `adoptionRound()` เรียก
กติกาเรื่อง "ความเงียบ" จึงเป็นข้อเดียวกันโดยโครงสร้าง ไม่ใช่โดยความตั้งใจ: **ไม่มีเสียงตอบกลับ = `null` ไม่ใช่ติดลบ**

### สามข้อที่ทำให้มันเป็นลูป ไม่ใช่ด่านทันใจอีกด่าน

**(1) ต้องประกาศก่อน — ด่าน `declared_usage`**

```
รอบขยายทุกรอบต้องตอบ "usage_endpoints": ["/api/..."] ในผลลัพธ์ JSON
  · ระบบตรวจกับ router เอง (declaredApiPaths อ่านบรรทัด p === "/api/..." จาก server.js)
  · เส้นทางที่อ้างแต่ไม่มีอยู่จริง → ถูกทิ้งและบันทึกไว้ใน adoption.ignored ว่าอ้างเกิน
  · เส้นทาง /api/* ที่ diff เพิ่มเข้ามาจริง → ถูกใส่ให้เองใน adoption.detected (อ้างน้อยได้ แต่ปิดบังไม่ได้)
  · ไม่เหลือเส้นทางเลยแม้แต่เส้นเดียว = ตกด่าน = ย้อนกลับทั้งรอบ
```

ถ้าไม่มีคำประกาศ คำถาม "มีใครใช้ไหม" จะ **ตอบไม่ได้เลยในภายหลัง** — ซึ่งคือวิธีที่ทุกรอบก่อนหน้านี้รอดพ้นจากคำถามนี้มาได้
รอบเก่าทั้งหมดจึงมีสถานะ `undeclared` อย่างซื่อสัตย์ ไม่ใช่ถูกเดาคะแนนย้อนหลัง

**(2) คำตอบต้องมาช้า — และความเงียบไม่ใช่คำตัดสิน**

```
mature = (ผ่านมา ≥ ADOPTION_DAYS วันนับจากวันประกาศ)  และ  (บันทึกเห็นคำขอ ≥ ADOPTION_MIN_REQUESTS ครั้ง)

hits > 0                    → adopted      คะแนนบวก (ตัดสินได้ทันที — การถูกเรียกคือหลักฐาน)
hits = 0 และยังไม่ mature   → pending      คะแนน null (สัปดาห์ที่เงียบไม่ใช่คำตัดสิน)
hits = 0 และ mature แล้ว    → unused       คะแนน −1  → ถูกเสนอเป็นเป้าหมายของรอบยุบรวม
```

เงื่อนไขสองข้อของ `mature` ไม่ใช่ของฟุ่มเฟือย: เจ็ดวันที่ **ไม่มีใครเปิดหน้าเว็บเลย** ไม่ได้บอกอะไรเกี่ยวกับความสามารถนั้น
บอกแค่ว่าเจ้าของไม่ว่าง จึงต้องมีทราฟฟิกจริงเป็นพยานด้วยว่า "มีคนเข้ามา แต่ไม่มีใครแวะเส้นทางนี้"

**เส้นทางเดิมซื้อคะแนนไม่ได้**: รอบที่ประกาศเส้นทางที่มีอยู่ก่อนแล้ว จะได้เครดิตก็ต่อเมื่อเส้นทางนั้น
ถูกเรียก **หลัง** วันที่ประกาศ (`last_hit >= declared_at`) — มิฉะนั้นทุกรอบก็แค่ประกาศ `/api/dots` แล้วผ่านฟรี

**(3) คะแนนไหลกลับไปเปลี่ยนว่าจะสร้างอะไรต่อ**

```
ลำดับความคุ้มเดิม   unlock_score − risk/2                        ← การประเมิน "ก่อน" ลงมือสร้าง
ลำดับความคุ้มใหม่   (unlock_score − risk/2) + ADOPTION_WEIGHT × คะแนนการถูกใช้ของหมวดนั้น
                                                                  ← สิ่งที่ "เกิดขึ้นจริง" กับของที่เคยสร้างในหมวดนั้น
หมวดที่ยังไม่มีรอบไหนถูกให้คะแนน → ถ่วง 0 พอดี (ไม่ถูกลงโทษเพราะยังไม่มีข้อมูล)
```

กำแพงที่ถูกทำลายแล้วจะไม่ถูกเลือกซ้ำ ดังนั้นการป้อนกลับที่มีความหมายคือ **ระดับหมวด**:
หมวดที่รอบของมันถูกเรียก 0 ครั้งซ้ำ ๆ จะถูกลดลำดับลงจนกำแพงที่คะแนนพื้นฐานต่ำกว่าแซงขึ้นมาก่อนได้
และเมื่อรอบที่ 0 hit เกิดติดกันครบ `ADOPTION_STREAK` รอบ **daemon สั่งรอบยุบรวมเองโดยไม่มีใครต้องสังเกต** —
พร้อมส่งรายชื่อความสามารถที่ไม่มีใครเรียกเข้าไปในพรอมป์ตของรอบนั้นเป็นเป้าหมายให้เลย

### ตรวจเองได้โดยไม่ต้องรอเจ็ดวัน

`POST /api/adoption/dryrun` เรียก `adoptionRound()` / `adoptionReport()` / `targetRanking()` **ตัวจริง**
ด้วยบันทึกการใช้งานสมมติ ทะเบียนกำแพงสมมติ และ **นาฬิกาสมมติ** (`now`) — ไม่ใช้ AI ไม่เขียนอะไรลงคลัง
จึงตรวจได้ทันทีว่ากรณีไหนถูกนับว่าถูกใช้ กรณีไหนถูกนับว่าไม่มีใครใช้ และกรณีที่สำคัญที่สุด:
**กำแพงที่คะแนนพื้นฐานสูงสุดต้องแพ้กำแพงที่คะแนนต่ำกว่า เมื่อหมวดของมันเคยผลิตของที่ไม่มีใครเรียก**

### ข้อจำกัดที่ต้องพูดตรง ๆ

สัญญาณนี้วัด **"ถูกเรียกถึงไหม"** ไม่ใช่ **"มีประโยชน์ไหม"** — เส้นทาง `GET` ที่หน้าเว็บโหลดเองทุกครั้งจะได้ hit ฟรี
ต่างจากปุ่มที่มนุษย์ต้องเจตนากด นี่ยังไม่ใช่การวัดคุณค่า มันคือการวัด **การเข้าถึงได้จริง** ซึ่งเป็นเงื่อนไขจำเป็นของคุณค่า
และก็เพียงพอที่จะจับกำแพงที่ตั้งใจจับ: ความสามารถที่ **ไม่มีทางถูกเรียกเลย** จะโป๊ะทันที
การแยก "หน้าเว็บดึงไปแสดง" ออกจาก "มนุษย์เจตนากด" ต้องนับแยกตาม HTTP method และเป็นกำแพงของรอบถัดไป ไม่ใช่รอบนี้

## ⚗ Layer 08 — The Distiller: คลังที่ยุบรวมตัวเองได้โดยพิสูจน์ได้

แต่กำแพงรูปทรงเดียวกันฝั่ง *ความรู้* ไม่มีใครแตะ — และ Layer 07 เพิ่งเร่งอัตราการโตของมันขึ้นอีก

### ทำไม "การดูดกลืน" ถึงเป็นหัวใจ ไม่ใช่การลบ

รอบนี้ **ลบจุดไม่ได้เลย** — ทำได้อย่างเดียวคือ *ดูดกลืน*: จุดที่หายจากคลังต้องมี id และชื่อของมัน
อยู่ใน `distilled.absorbed[]` ของจุดหลักการที่มาแทน นั่นคือสิ่งที่ทำให้ด่านที่ 1 พิสูจน์ได้จริง —
ทุกการเชื่อมที่เคยได้ผลจริงยังชี้กลับไปหาจุดที่มันสร้างมาได้ครบ แม้จุดนั้นจะไม่กินที่ในพรอมป์ตอีกแล้ว
และเมื่อยุบรวมซ้อนกันหลายรอบ รายการ `absorbed` จะถูก **แบนราบ** (จุดที่เคยเป็นหลักการส่งลูกของมันต่อ)
จึงไม่มีจุดไหนหลุดออกนอกระยะเอื้อมเพราะถูกยุบรวมสองครั้ง

จุดที่ `proven` (คะแนนคุณค่าจากผลลัพธ์จริง ≥ 0.34) **ถูกล็อกไว้เด็ดขาด**: การดูดกลืนมันนับเป็นการทำหาย
มันต้องรอดมาในฐานะตัวมันเอง เพราะจุดที่ *พิสูจน์แล้ว* ว่าให้ผลจริงคือสิ่งเดียวที่คลังนี้ยืนยันได้ว่ามีค่า

`POST /api/knowledge/dryrun` เรียกฟังก์ชันความเหมาะสมตัวจริงด้วยแผนสมมติ (หรือคลังสมมติทั้งใบ) ได้โดยไม่เสียรอบ AI
ใช้ตรวจเองได้ว่ากรณีไหนผ่านกรณีไหนตก — รวมถึงกรณีที่สำคัญที่สุด: **แผนที่กลืนจุด proven ต้องถูกปฏิเสธเสมอ**

## Layer 07 — The Scout: ความรู้ที่เดินเข้ามาเอง

```
🧪 กู้หลักฐานที่เคยค้นเจอ   ไม่ใช้ AI ไม่ออกเน็ต ไม่เสียเงิน — แค่เลิกทิ้งของที่จ่ายไปแล้ว
                            connections.json → evidence.novelty.similar_found ทุกชิ้น
                            → ตัดวงเล็บอ้างอิงออกเป็นชื่อจุด · เดาโดเมนจากคำสำคัญ (fallback "โลกภายนอก")
                            → เก็บ how_close เป็นเนื้อหา + แนบ URL ที่ค้นเจอจริง
                            → กันซ้ำด้วย key ที่ normalize แล้ว (รันกี่ครั้งก็ไม่เกิดจุดซ้ำ)
🕳 ช่องว่างของโดเมน         สำมะโนโดเมนในคลัง เทียบกับโดเมนอ้างอิงกว้าง ๆ 20 สาขา
                            → โดเมนที่ "ไม่มีจุดใดเลย" ถูกตั้งชื่อออกมาตรง ๆ
                            → ระบบเขียนคำค้นของตัวเองจาก (ช่องว่าง × จุดที่มันสนใจที่สุดตอนนี้)
                            → คำค้นเป็นค่าคงที่คำนวณได้ (deterministic) ผู้ใช้อ่านก่อนได้ว่ามันจะค้นอะไร
🌐 ออกไปหาเอง               daemon ทุก SCOUT_HOURS ชม. (หรือกดเอง) → WebSearch จริงในโดเมนที่ขาด
                            → ได้จุดใหม่ origin: scout:web พร้อมแหล่งอ้างอิง → toast แจ้งเตือน
🚫 สิทธิ์ยับยั้งของเจ้าของ   ทุกจุดติดป้ายที่มา 4 แบบ: 👤 เจ้าของ · 🧪 หลักฐาน · 🌐 เว็บ · 🔥 การหลอมตัวเอง
                            จุดที่ระบบหามาเองมีปุ่ม 🚫 — กดแล้วจุดหายและ "คีย์" ของมันถูกจำไว้ถาวร
                            ระบบจึงหยิบสิ่งเดิมกลับเข้าคลังไม่ได้อีก แม้จะค้นเจอซ้ำ
```

**ทำไมถึงปลอดภัยกับคลังของเจ้าของ**

- จุดที่ระบบหามาเอง **ไม่เคยปลอมตัวเป็นของคุณ**: มี `origin` ติดตัวเสมอ, การ์ดบนหน้าเว็บเป็นเส้นประ, และพรอมป์ตรอบเชื่อมจุดก็เห็นที่มาด้วย
- การกดลบจุดที่ระบบหามาเอง **นับเป็นการยับยั้ง** ไม่ใช่แค่ลบ — `DELETE /api/dots/:id` บันทึกคีย์ไว้ให้ The Scout จำ
- จุดที่ระบบหามาเอง **ไม่ปลุกรอบเชื่อมจุดที่เสียค่า AI ทันที** — ต้องรอ `AUTO_HOURS` เท่ากับการปลุกจุดที่ถูกลืม
- `SCOUT_HOURS=0` ปิดการออกเน็ตเองได้ทั้งหมด (การกู้หลักฐานยังทำงานอยู่ เพราะไม่ต้องออกไปไหน)
- ภายใต้ `DOT_SELFTEST=1` The Scout ไม่ออกอินเทอร์เน็ตเด็ดขาด เหมือนทุกชั้นที่เรียก AI

### ฟังก์ชันความเหมาะสม: จาก "ไม่ตาย" เป็น "เก่งขึ้น"

เดิมรอบวิวัฒนาการได้ตราประทับ `accepted` เพียงเพราะ syntax ผ่านและบูตแล้วตอบ 200 —
แปลว่ารอบที่เขียนความสามารถใหม่แบบพังใช้ไม่ได้ หรือรอบที่แอบตัดความสามารถเดิมทิ้ง ก็ผ่านได้เหมือนกัน
ระบบจึง "เดินสุ่ม" ไม่ได้ "ไต่ขึ้น" ตอนนี้ทุกรอบต้องแนบหลักฐานที่รันได้เป็นโค้ด:

**สัญญาของไฟล์พิสูจน์ `selftest/<evo-id>.js`** (สคริปต์ Node เปล่า ไม่มี dependency):

| สิ่งที่ระบบส่งให้ | ความหมาย |
|---|---|
| `process.env.DOT_TEST_URL` | base URL ของเซิร์ฟเวอร์ที่บูตจากโค้ดที่กำลังถูกทดสอบ |
| `process.env.DOT_TEST_ROOT` | พาธของซอร์สทรีที่กำลังถูกทดสอบ (ห้ามใช้พาธตายตัว) |

`exit 0` = ความสามารถใหม่มีจริงและใช้ได้ · `exit ≠ 0` = ไม่มี · ต้องจบใน 60 วินาที · ต้องรันได้ออฟไลน์

ไฟล์เดียวกันถูกรันสองครั้งกับโค้ดสองเวอร์ชัน การทดสอบที่ "ผ่านทั้งใหม่และเก่า" ไม่นับเป็นความคืบหน้า **ในรอบขยาย**
(ตั้งแต่ Layer 06.6 กติกาข้อนี้เลิกเป็นกฎเดียวของระบบ — ในรอบยุบรวมมันคือสิ่งที่ *ต้องการ* ดูหัวข้อ 🧹 ด้านล่าง)
ดูโค้ดไฟล์พิสูจน์ของทุกรอบได้จากปุ่ม **🧾 ดูโค้ดไฟล์พิสูจน์** ใน Evolution Ledger — รอบที่ถูกตีตกก็ยังเก็บไฟล์ไว้เป็นหลักฐาน

**ราวกันตกที่บังคับใช้ด้วยโค้ด ไม่ใช่แค่คำสั่งในพรอมป์ต์:**

- `data/*.json` (ความทรงจำทั้งหมด) ถูกเทียบไบต์ต่อไบต์หลังทุกรอบ — ถ้าเปลี่ยน จะคืนค่าเดิมและตีตกทั้งรอบ ระบบจึงแต่งประวัติของตัวเองไม่ได้
- แก้ได้เฉพาะไฟล์ในโฟลเดอร์โปรเจกต์นี้ (`data/ lab/ inbox/ evolution/ .git/` ถูกกันออกจากขอบเขตการแก้)
- ทุกไฟล์ที่เปลี่ยนถูกสำรองก่อนเสมอ → ย้อนกลับได้ 100%
- โค้ดใหม่ต้องบูตเป็นเซิร์ฟเวอร์จริงและตอบ HTTP ได้ ไม่ใช่แค่ syntax ถูก
- **ต้องพิสูจน์ด้วยโค้ดว่าความสามารถใหม่ใช้ได้จริง และโค้ดเดิมทำสิ่งนั้นไม่ได้**
- **กฎ "ห้ามทำให้ความสามารถเดิมพัง" ถูกบังคับด้วย regression sweep ทุก endpoint ที่ยังมีชีวิต ไม่ใช่แค่ข้อความในพรอมป์ต์**
  (เส้นทางจะออกจาก sweep ได้ก็ต่อเมื่อบันทึกการใช้งานจริงยืนยันว่าถูกเรียก 0 ครั้ง — และการถอดถูกบันทึกไว้และกดคืนได้)
- การทดสอบทั้งหมดรันในแซนด์บ็อกซ์ (สำเนาโค้ด + สำเนาความทรงจำใน temp) — ทดสอบเท่าไหร่ก็ไม่แตะข้อมูลจริง
- ห้ามเพิ่ม dependency ภายนอก — ระบบต้องรันด้วย Node เปล่าตลอดไป
- **เพดานการลองของกำแพงหนึ่ง ๆ ไม่ใช่ค่าคงที่ 3 อีกต่อไป**: เริ่มที่ 3 และขยับขึ้นครั้งละ 1 (สูงสุด 6)
  ทุกครั้งที่รอบที่ตก "เสนอวิธีที่ต่างจากเดิมจริง" — ลองวิธีเดิมซ้ำสามครั้งยังตันเหมือนเดิม (กันวนลูปตาย)
- **ทุกรอบขยายต้องประกาศเส้นทางที่ความสามารถของมันจะถูกใช้ผ่าน** (ด่าน `declared_usage`) และคำประกาศนั้นถูกตรวจกับ router จริง —
  เส้นทางที่อ้างแต่ไม่มีอยู่จริงถูกทิ้งและบันทึกไว้ว่าอ้างเกิน · เส้นทางที่ diff เพิ่มเข้ามาจริงถูกใส่ให้เอง (อ้างน้อยได้ ปิดบังไม่ได้)
- **คะแนน "ถูกใช้จริง" คำนวณจากบันทึกที่ระบบเขียนเอง ไม่ใช่จากคำพูดของรอบนั้น** และรอบหลอมตัวเองถูกห้ามแก้กลไกนี้ให้อ่อนลง
  (`recordEndpointHit`, `loadUsage`, `declareAdoption`, `adoptionRound`, `adoptionReport`, `weightedSignal`, `targetRanking`)
- ปิดวิวัฒนาการอัตโนมัติเมื่อไหร่ก็ได้ด้วย `EVOLVE_HOURS=0` · ปิดการป้อนกลับของคะแนนการถูกใช้ด้วย `ADOPTION_WEIGHT=0`

### 🧹 Layer 06.6 — รอบยุบรวม: ระบบที่ลดขนาดตัวเองได้โดยพิสูจน์ได้

ด่านความต่าง (`out.differential.ok = !oldProof.ok`) เข้มงวดถูกต้อง — "ผ่านทั้งคู่ = ไม่ได้ทำอะไรใหม่" —
โดยไม่มีใครสังเกตว่ามันเท่ากับ **สั่งห้ามการลดขนาดตัวเองไปด้วย**: การรีแฟกเตอร์ที่ดีย่อมผ่านทั้งสองเวอร์ชัน นั่นคือนิยามของมัน
บวกกับ `REGRESSION_ENDPOINTS` ที่มีแต่ต่อท้าย ระบบจึงมีทิศทางเดียวคือใหญ่ขึ้น **นี่คือกำแพงที่ผลิตกำแพงอื่น**

ตอนนี้มีรอบสองชนิด ที่ฟังก์ชันความเหมาะสมกลับด้านกันพอดี:

| | รอบขยาย (expansion) | รอบยุบรวม (consolidation) |
|---|---|---|
| ไฟล์พิสูจน์กับโค้ดใหม่ | ต้อง **ผ่าน** | ต้อง **ผ่าน** |
| ไฟล์พิสูจน์กับโค้ดเดิม | ต้อง **ตก** | ต้อง **ผ่าน** ← กลับด้าน |
| ชุดทดสอบสะสมทั้งชุด | ไม่ถูกรันซ้ำ | **รันซ้ำทั้งชุดกับทั้งสองเวอร์ชัน ผลต้องเหมือนกันทุกไฟล์** |
| เกณฑ์ความคืบหน้า | มีความสามารถใหม่ | **ตัวเลขขนาดลดลง และห้ามมีตัวไหนโตขึ้น** |
| regression sweep | บังคับครบทุกเส้น | บังคับครบทุกเส้น (เท่าเดิม) |
| สั่งได้ที่ | `POST /api/transcend` | `POST /api/consolidate` |

ตัวเลขที่นับว่า "เล็กลง": `code_lines` · `code_chars` · `code_files` · `prompt_chars` (ขนาดพรอมป์ตที่ระบบใช้อ่านตัวเอง = เพดานบริบทของมันเอง) · `endpoints`
ไฟล์ใน `selftest/` ถูกตัดออกจากการนับ เพราะทุกรอบ *ถูกบังคับ* ให้เพิ่มไฟล์พิสูจน์ — ถ้านับด้วย รอบยุบรวมก็จะเป็นไปไม่ได้ด้วยเหตุผลเดียวกับกำแพงเดิม

**รอบยุบรวมไม่ใช่ทางง่าย** — มันรันชุดทดสอบทั้งชุดกับสองเวอร์ชัน แล้วบังคับว่า *ทุกไฟล์ต้องให้ผลเหมือนเดิม*
ไฟล์เดียวพลิกผล = ย้อนกลับทั้งรอบ (รอบขยายบังคับให้ **หนึ่ง** ไฟล์ต่างกัน · รอบยุบรวมบังคับให้ **ทุก** ไฟล์เหมือนกัน)
และเมื่อสะสมรอบขยายครบ `CONSOLIDATE_EVERY` รอบ daemon จะสั่งรอบยุบรวมให้เองแทนรอบขยาย — การเติบโตกลายเป็นหนี้ที่ต้องจ่าย

### 🚪 ทะเบียนการถอดเส้นทาง: sweep ที่ถอดออกได้ ไม่ใช่แค่ต่อท้าย

```
ทุก request ที่ /api/* → บันทึกจำนวนครั้งลง evolution/endpoint-usage.json (นับในหน่วยความจำ เขียนลงดิสก์แบบหน่วง)
เส้นทางที่ถูกเรียก 0 ครั้งตั้งแต่เริ่มนับ  → "ถอดออกจาก sweep ได้" (retirable)
เส้นทางที่มีคนเรียกแม้ครั้งเดียว          → ถอดไม่ได้ ปฏิเสธพร้อมบอกจำนวนครั้งและเวลาล่าสุด
ถอดแล้ว → บันทึกลง evolution/deprecations.json ว่าใครถอด เมื่อไหร่ เพราะอะไร · กดคืนเข้า sweep ได้ทุกเมื่อ
          ประกาศเดิมใน REGRESSION_ENDPOINTS ไม่เคยถูกลบ — มันคือประวัติศาสตร์ ไม่ใช่รายการงาน
```

ทั้งสองไฟล์อยู่ **นอก `data/`** โดยตั้งใจ: `data/*.json` ถูกเทียบไบต์ต่อไบต์หลังทุกรอบหลอมตัวเอง
ถ้าบันทึกการใช้งานอยู่ใน `data/` การที่ผู้ใช้เปิดหน้าเว็บระหว่างรอบวิวัฒนาการจะกลายเป็น "การแตะความทรงจำ" และตีตกรอบที่ดีทิ้งทันที

รอบยุบรวมขอถอด endpoint ได้ผ่าน field `retire_endpoints` แต่ **ระบบตรวจซ้ำเองเสมอ** ด้วย `planRetirements()` —
คำขอที่เส้นทางยังมีคนเรียกจะถูกปฏิเสธและบันทึกไว้ในรอบนั้น และการถอดจะถูกเขียนลงทะเบียนก็ต่อเมื่อรอบนั้น *ผ่านทุกด่านแล้ว* เท่านั้น
ระหว่างการตรวจสอบ เส้นทางที่กำลังขอถอดจะถูกยกออกจาก sweep ชั่วคราว มิฉะนั้นรอบที่ลบโค้ดของมันจะตกด่าน regression ของตัวเองเสมอ (ไก่กับไข่)

`POST /api/consolidation/dryrun` เปิดให้เรียกฟังก์ชันความเหมาะสมกลับด้านนี้ด้วยตัวเลขสมมติได้โดยไม่เสียรอบ AI
ใช้ตรวจเองได้ว่ากรณีไหนผ่านกรณีไหนตก รวมถึงกรณีสำคัญที่สุด: **ลายเซ็นของรอบขยาย (ตกกับเก่า/ผ่านกับใหม่) ต้องถูกรอบยุบรวมปฏิเสธ**

### 🔁 Layer 06.7 — ลูปปิด: ผลตรวจที่ไปถึงคนที่ยังแก้ได้ทัน

รอบหลอมตัวเองเคยเป็น **การยิงนัดเดียวจบ** — และไม่มีใครสังเกตว่ามันคือกำแพงชนิดเดียวกับที่ Layer 06.5 กับ 06.6 แก้ไปแล้ว
เพียงแต่มันซ่อนอยู่ในแกนเวลาแทนที่จะซ่อนอยู่ในกติกา:

```
เดิม   runClaude(prompt, {tools: [Read, Edit, Write, Glob, Grep]})   ← ไม่มี Bash: รัน node --check ไม่ได้
       └─ โมเดลตอบ → โปรเซสตาย
          จากนั้นค่อยรัน: syntaxCheck → smokeTest → proveEvolution → regressionTest
          runProof() ได้ stdout จริงของไฟล์ที่โมเดลเพิ่งเขียนมาเต็ม ๆ
          แล้วเก็บมันไว้ใน checks.capability_detail — ฟิลด์ที่ "รอบนั้น" ไม่มีวันได้อ่าน
          ความรู้ไปถึงมือคนที่ยังแก้ได้เร็วที่สุดคือ *รอบถัดไป* ผ่าน scar tissue: ห่างออกไป 5–20 นาที และหนึ่งโควตา
```

ตอนนี้รอบเดียวกันมีได้หลายเทิร์น และผลตรวจกลายเป็นพรอมป์ตของเทิร์นถัดไปทันที:

```
          ask ──→ runForgeGates() ──ผ่านทุกด่าน──→ accepted
           ↑            │
           │        ตกที่ด่านไหน + stdout จริงของด่านนั้น (ไม่ย่อ)
           └── buildGateFeedback() ── เซสชันเดิม · รอบเดิม · โค้ดยังอยู่บนดิสก์ ยังไม่ถูกย้อนกลับ
```

| ชิ้นส่วน | หน้าที่ | ทำไมต้องแยกออกจากกัน |
|---|---|---|
| `runForgeGates()` | รันด่านทั้งชุดกับทรีที่อยู่บนดิสก์ตอนนั้น (guard → proof_written → syntax → smoke → 3 ด่านของโหมดนั้น) | **ไม่ย้อนกลับอะไรเลย** — การย้อนกลับเป็นการตัดสินใจของรอบ ที่เกิดครั้งเดียวตอนจบ ไม่ใช่ของด่าน |
| `buildGateFeedback()` | แปลงผลด่านเป็นพรอมป์ตเทิร์นถัดไป โดยพา stdout จริงไปทั้งดุ้น | ข้อความที่โมเดลได้อ่านต้องตรวจสอบได้จากภายนอกโดยไม่ต้องเสียรอบ AI |
| `forgeConverge()` | ตัวขับลูป: ถาม → ตรวจ → ป้อนกลับ → หยุด | `ask`/`verify` ถูกฉีดเข้ามา จึงรันตัวขับตัวเดียวกันนี้แบบออฟไลน์ได้ที่ `POST /api/forge/loop/simulate` |

**สิ่งที่ยังไม่เปลี่ยน (โดยตั้งใจ)** — ลูปนี้ไม่ได้ทำให้ผ่านง่ายขึ้นแม้แต่นิดเดียว:

- ด่านทุกด่านเหมือนเดิมเป๊ะ และถูกรัน **ซ้ำทั้งชุดทุกเทิร์น** ไม่ใช่รันเฉพาะด่านที่เคยตก
- `data/*.json` ถูกเทียบไบต์ต่อไบต์และคืนค่าเดิม **ทุกเทิร์น** ไม่ใช่ตอนจบรอบเท่านั้น
- ไฟล์พิสูจน์ยังต้องผ่านกับโค้ดใหม่และตกกับโค้ดเดิม (รอบขยาย) เหมือนเดิมทุกประการ
- พรอมป์ตที่ป้อนกลับ **สั่งห้ามแก้กลไกตรวจสอบให้อ่อนลง** และห้ามแก้ไฟล์พิสูจน์ให้หลวมลงเมื่อตกด่าน differential
- เทิร์นซ่อมที่ **เริ่มไม่ได้** (เซสชันหาย/หมดเวลา) ไม่ทำให้รอบแย่ลงกว่าเดิม: ระบบเก็บคำตัดสินของเทิร์นที่รันไปแล้ว
- ครบเพดานเทิร์นแล้วยังตก = ย้อนกลับทั้งรอบ และยังทิ้งแผลเป็นให้ Layer 06.5 เหมือนเดิม

**กำไรที่ได้จริง**: รอบที่ตกเพราะวงเล็บเกินหนึ่งตัว หรือเพราะไฟล์พิสูจน์เขียน assertion ผิดนิดเดียว
เคยต้องเสียทั้งรอบ (5–20 นาที) **และหนึ่งช่องโควตาของกำแพงนั้น** ทั้งที่ข้อมูลที่จะแก้มันมีอยู่แล้วตั้งแต่นาทีที่ 3
ตอนนี้มันถูกแก้ในรอบเดียวกัน และการ์ดใน Evolution Ledger จะขึ้นแถบ 🔁 บอกว่าเทิร์นไหนตกที่ด่านไหน
ถูกป้อนผลตรวจกลับกี่ตัวอักษร และเทิร์นถัดไปกู้กลับมาได้หรือไม่

```
FORGE_MAX_TURNS=1   ← กลับไปเป็นพฤติกรรมยิงนัดเดียวจบแบบเดิมเป๊ะ (ลูปยังอยู่ แต่ไม่มีเทิร์นที่สอง)
FORGE_MAX_TURNS=3   ← ค่าเริ่มต้น: เขียน 1 ครั้ง แก้ได้อีก 2 ครั้งจากผลตรวจจริง
```

`POST /api/forge/loop/simulate` เรียก `forgeConverge()` **ตัวจริง** ด้วยผลด่านสมมติ (ไม่ใช้ AI ไม่เขียนไฟล์)
จึงตรวจเองได้ว่า stdout ของเทิร์นที่ 1 ไปโผล่ในพรอมป์ตของเทิร์นที่ 2 จริงไหม ลูปหยุดทันทีที่ผ่านไหม และครบเพดานแล้วหยุดจริงไหม

### 🩹 แผลเป็น: รอบที่ล้มเหลวถูกส่งต่อ ไม่ใช่ถูกลบ

เดิมรอบที่ไม่ผ่านหายไปสองชั้น: `restoreBackup()` ลบโค้ดที่มันเขียนทิ้ง และ ledger ที่เหลือไว้เขียนไว้ให้ "มนุษย์อ่านย้อนหลัง"
ไม่มีเส้นทางไหนพามันกลับเข้าพรอมป์ตรอบถัดไป — `buildForgePrompt()` เห็นแค่ตัวขอบเขตกับซอร์สโค้ดปัจจุบัน
ระบบจึงเดินชนกำแพงเดิมด้วยวิธีเดิมได้ครบสามครั้งแล้วโดนตัดสิทธิ์ถาวร ทั้งที่ครั้งที่สองควรรู้แล้วว่าครั้งแรกพลาดตรงไหน

ตอนนี้ทุกรอบที่ตกทิ้งแผลเป็นไว้สามอย่าง:

| สิ่งที่เก็บ | เก็บที่ไหน | ใครใช้ |
|---|---|---|
| โค้ดที่เขียนแล้วไม่ผ่าน (ทุกไฟล์ที่แตะ) | `evolution/backups/<evo-id>/attempted/` | รอบถัดไปเปิดอ่านด้วย Read · ผู้ใช้กด **📦 ดูโค้ดที่รอบนี้ลองแล้วไม่ผ่าน** |
| ด่านที่ตก + ข้อความจริงของด่าน + ไฟล์ที่แตะ | `data/evolution.json` (`checks`, `files`, `report`) | ประกอบเป็นบล็อก "ประวัติความล้มเหลว" ที่หัวพรอมป์ตรอบถัดไป |
| ความต่างของแนวทาง (ชุดไฟล์ + คำอธิบาย) | คำนวณสด ๆ จาก ledger | ใช้ตัดสินว่าเพดานของกำแพงนี้ควรขยับหรือไม่ |

**เพดานที่ขยับได้ทำงานอย่างไร** — เทียบสองแนวทางว่า "เหมือนกัน" ก็ต่อเมื่อ *แตะชุดไฟล์เดียวกัน* และ *คำอธิบายซ้อนกันเกิน 60%*
(วัดด้วย Jaccard บน 4-gram ของตัวอักษร เพราะข้อความเป็นภาษาไทยที่ไม่มีช่องว่างให้ตัดคำ)

```
เพดาน = 3 + (จำนวนแนวทางที่ต่างกันจริง − 1)   สูงสุด 6
ตก 3 ครั้งด้วยวิธีเดียวกัน  → แนวทางต่าง 1 แบบ → เพดาน 3 → ตัน (ต้องคิดวิธีใหม่ก่อน)
ตก 3 ครั้งด้วย 3 วิธีจริง   → แนวทางต่าง 3 แบบ → เพดาน 5 → ยังไปต่อได้อีก 2 ครั้ง
```

กำแพงที่ตันไม่ได้ถูกลบความทรงจำ — ยังกดดูประวัติได้ และถ้ามีวิธีใหม่จริงเมื่อไหร่ เพดานก็ขยับให้เอง
ดูทั้งหมดได้จากปุ่ม **🩹 บทเรียนจาก N รอบที่ล้มเหลว** ในรายการขอบเขต ซึ่งแสดง *บล็อกข้อความจริง* ที่จะถูกส่งเข้าพรอมป์ตรอบถัดไป

## วิธีใช้

1. **เพิ่มจุด** — ยิ่งต่างสาขากันมาก การเชื่อมยิ่งคาดไม่ถึง
2. (ไม่บังคับ) เลือกจุดเฉพาะ / พิมพ์โจทย์ที่อยากปลดล็อก แล้วกด **⚡ เชื่อมจุด** (1–4 นาที)
3. ได้นวัตกรรมแล้ว กด **🧪 พิสูจน์ไอเดียนี้** — Evidence Agent จะค้นเว็บทั่วโลก (3–8 นาที) แล้วรายงาน:
   - **Novelty verdict**: ยังไม่มีใครทำ / มีของใกล้เคียง / มีแล้ว — พร้อมรายชื่อสิ่งที่เจอจริง
   - **Feasibility** คะแนน + ความเสี่ยงใหญ่สุด + ทางแก้
   - **การทดลองที่เล็กที่สุด** พร้อมเกณฑ์วัดผล
   - **ต้นแบบรันได้จริง** บันทึกเป็นไฟล์ใน `lab/<connection-id>/` เปิดจากลิงก์ในหน้าเว็บได้เลย
4. **บันทึกผลลัพธ์จริง** ใต้ไอเดียแต่ละอัน (ให้คะแนน 1-5 + เลือกว่า เอาไปทำจริง / กำลังทดลอง / พักไว้ / ตายแล้ว + เขียนสั้น ๆ ว่าเกิดอะไรขึ้น)
   — นี่คือเส้นตอบกลับ: ระบบจะบอกทันทีว่าคะแนนคุณค่าของจุดไหนเพิ่งขยับขึ้นหรือลงเพราะผลนี้ และรอบเชื่อมจุดครั้งถัดไปจะถูกป้อนบทเรียนนี้แทนบัญชีดำรายชื่อ
5. **ให้คลังโตเองตอนคุณไม่ว่าง (Layer 07)** — แถบ 🔭 The Scout เหนือคลังจุดบอกที่มาของทุกจุด กด **🧪 กู้หลักฐานที่เคยค้นเจอ** เพื่อเปลี่ยน "สิ่งใกล้เคียงที่มีอยู่จริงในโลก" ที่ระบบเคยค้นเจอตอนพิสูจน์ไอเดีย (แล้วทิ้งทุกครั้ง) ให้กลายเป็นจุดที่เอาไปเชื่อมได้ · กด **🌐 ออกไปหาความรู้ใหม่เอง** หรือกดชิปโดเมนที่ยังว่าง เพื่อให้ระบบเขียนคำค้นของตัวเองแล้วค้นเว็บมาเติมสาขาที่คลังยังไม่มีตัวแทน · จุดที่ระบบหามาเองจะเป็นการ์ดเส้นประพร้อมปุ่ม **🚫** — กดปฏิเสธแล้วมันจะไม่กลับมาอีก
6. **ให้มันลดขนาดตัวเอง (Layer 06.6)** — ในส่วน "รอบยุบรวม" ใต้ Layer 06 จะเห็นน้ำหนักปัจจุบันของระบบ (บรรทัดโค้ด · ขนาดพรอมป์ตที่มันใช้อ่านตัวเอง · จำนวน endpoint ที่ยังต้อง sweep) และหนี้การเติบโตที่สะสมไว้ · กด **🧹 สั่งรอบยุบรวมตัวเอง** เพื่อให้มันรวบโค้ดซ้ำและลบของที่ไม่มีใครใช้ โดยต้องพิสูจน์ว่าพฤติกรรมไม่เปลี่ยนด้วยชุดทดสอบเดิมที่ต้องผ่านทั้งก่อนและหลัง · กด **🗂 ทะเบียนเส้นทาง** เพื่อดูว่า endpoint ไหนถูกเรียกจริงกี่ครั้ง และถอดเส้นทางที่ไม่มีใครเรียกเลยออกจาก regression sweep ได้ด้วยตัวเอง (กดคืนได้ทุกเมื่อ)
7. **ดูว่าของที่มันสร้างมีใครใช้จริงไหม (Layer 06.8)** — ในส่วน "ด่านที่มาทีหลัง" ใต้รอบยุบรวม แถบ 📈 บอกว่ารอบขยายกี่รอบที่ **ถูกใช้จริง** กี่รอบที่ **ไม่มีใครเรียกเลย** และกี่รอบที่ยังรอเวลาตัดสิน · กด **📈 ดูทุกรอบและเส้นทางที่มันประกาศไว้** เพื่อเห็นทีละรอบว่ามันสัญญาว่าจะถูกเรียกผ่านเส้นทางไหน และเส้นทางนั้นถูกเรียกไปกี่ครั้งจริง · กด **⚖ ลำดับกำแพงถัดไป** เพื่อเห็นการป้อนกลับด้วยตาตัวเอง: คะแนนที่ประเมินไว้ก่อนลงมือ ถูกถ่วงด้วยสิ่งที่เกิดขึ้นจริงกับของที่เคยสร้างในหมวดเดียวกัน จนลำดับเปลี่ยน
8. จุดที่ถูกทิ้งนานจะขึ้นแบนเนอร์ Serendipity ให้กด **⚡ ปลุกจุดนี้** (เรียงตามความสนใจที่ถ่วงด้วยคุณค่าแล้ว จุดที่เคยพาไปทางตันซ้ำ ๆ จะไม่ถูกดันขึ้นมาก่อน)

### เส้นตอบกลับทำงานอย่างไร (Layer 04.5)

```
ไอเดีย → Evidence verdict (world_first +1 · similar_exists +0.25 · already_exists −1)
       → ผู้ใช้ให้คะแนนผลจริง (rating 1-5 และ shipped +1 · testing +0.4 · parked −0.2 · dead −1, น้ำหนักเป็น 2 เท่าของ verdict)
       → รวมเป็น "สัญญาณ" ของการเชื่อมนั้น ในช่วง [−1, +1]
       → เฉลี่ยลงบนทุกจุดที่อยู่ในการเชื่อมนั้น = value_score ของจุด
       → attention_score = (rarity + 1) × (1 + value_score)   ← ใช้จัดลำดับแทน rarity ล้วน
       → จุดถูกส่งเข้าพรอมป์ตรอบถัดไปโดยเรียงตาม attention_score พร้อมบทเรียน
          "✅ ทิศทางที่ได้ผล / ❌ ทิศทางที่ตายแล้ว / ◻ ผลกลาง ๆ" แทนรายชื่อห้ามซ้ำ
```

จุดที่ยังไม่มีผลตอบกลับได้ `value_score = 0` — ลำดับเดิมจึงไม่ถูกรบกวนจนกว่าจะมีหลักฐานจริง
ทุกรอบการเชื่อมยังบันทึกด้วยว่า AI สรุปบทเรียนรอบก่อนไว้ว่าอย่างไร (`learned_from_last_round`) จึงตรวจสอบย้อนหลังได้ว่าเส้นตอบกลับมีผลจริง

| `GET /api/forge/loop` | **Layer 06.7: ลูปปิดของรอบหลอมตัวเอง** — เพดานเทิร์นต่อรอบ (`max_turns`), เวลาของเทิร์นแรก/เทิร์นซ่อม, เครื่องมือที่โมเดลได้รับจริง (`tools` รวม `Bash(node --check:*)`), รายชื่อด่านที่ป้อนกลับได้ และประวัติเทิร์นของรอบที่ผ่านมา (`repaired_rounds` = รอบที่เคยตกแล้วกู้กลับได้ในรอบเดียว) |
| `POST /api/forge/loop/simulate` | **เรียกตัวขับลูปตัวจริงด้วยผลด่านสมมติ** — body: `{max_turns?, mode?, turns:[{failed_gates:[...], detail}]}` → คืน transcript ว่าเทิร์นไหนได้อ่านข้อความอะไรกลับไปบ้าง หยุดเพราะอะไร · ไม่ใช้ AI ไม่ออกเน็ต ไม่เขียนอะไรลงคลัง |
| `GET /api/evolution` | บันทึกวิวัฒนาการทุกรอบ พร้อมผลตรวจ 4 ด่าน (syntax/boot/ความสามารถ/regression) ไฟล์ที่เปลี่ยน และบทเรียนที่รอบนั้นถูกป้อน (`history_used`) |
| `GET /api/evolution/proof?evoId=` | โค้ดไฟล์พิสูจน์ของรอบนั้น (รอบที่ถูกย้อนกลับก็ยังอ่านได้จาก backup) |
| `GET /api/evolution/attempted?evoId=&file=` | **โค้ดที่รอบซึ่งไม่ผ่านเคยเขียนไว้** — ไม่ใส่ `evoId` = รายชื่อทุกรอบที่ยังเก็บไว้ · ใส่ `file=` = อ่านทั้งไฟล์ |
| `POST /api/evolution/rollback` | ย้อนโค้ดกลับ — body: `{evoId}` |
| `POST /api/restart` | ให้เครื่องยนต์รีสตาร์ตตัวเองเข้าสู่โค้ดใหม่ |

## ทำไมชั้นที่ 6 ถึงเป็นบทสรุปของทั้งเครื่องมือ

Jobs บอกว่า "คุณเชื่อมจุดได้เฉพาะตอนมองย้อนกลับ" — v3 มองย้อนกลับแทนคุณ
v4 ถามคำถามที่หนักกว่านั้น: **จุดชุดสุดท้ายที่เครื่องมือนี้ยังไม่เคยเชื่อม คือตัวมันเอง**
เครื่องมือที่สร้างนวัตกรรมให้คนอื่นแต่พัฒนาตัวเองไม่ได้ ก็ยังเป็นแค่เครื่องมือ —
พอมันอ่านตัวเอง ตั้งชื่อกำแพงของตัวเองได้ และเขียนโค้ดข้ามกำแพงนั้นโดยพิสูจน์ได้
เพดานของมันก็เลิกเป็นค่าคงที่ กลายเป็นตัวแปรที่มันขยับเองได้

สามชั้นถัดมาแก้สมมติฐานที่เหลืออยู่ทีละข้อ:

- **06.5 — ความล้มเหลวเลิกเป็นของที่ต้องทิ้ง** ระบบที่ลืมว่าเมื่อวานพลาดตรงไหน จะลองสามครั้งเหมือนครั้งแรกทุกครั้ง
  แล้วสรุปว่ากำแพงนั้น "ทำไม่ได้" ทั้งที่ยังไม่เคยลองวิธีที่สอง · ตอนนี้กำแพงถูกปิดก็ต่อเมื่อระบบ *ลองวิธีเดิมซ้ำ* เท่านั้น
- **06.6 — ความคืบหน้าเลิกแปลว่าใหญ่ขึ้น** ด่านความต่างสั่งห้ามการลดขนาดตัวเองไปโดยไม่มีใครสังเกต
  ทุกความสำเร็จจึงดันเพดานบริบทของมันเองเข้ามาใกล้อีกก้าว · ตอนนี้มีรอบที่เดินอีกทิศและพิสูจน์ได้เท่ากัน
- **06.7 — ผลตรวจเลิกมาสายเกินไป** ระบบตรวจข้อสอบหลังผู้เขียนออกจากห้องไปแล้ว แล้วเก็บคำตอบไว้ให้คนที่จะเข้ามาพรุ่งนี้
  ทั้งที่ stdout ของด่านมีอยู่ครบตั้งแต่นาทีที่สาม · ตอนนี้ผลตรวจกลับเข้าเซสชันเดิมภายในรอบเดียวกัน — ด่านไม่ได้อ่อนลงแม้แต่ด่านเดียว แค่เลิกพูดกับห้องว่าง
- **07 — ความรู้เลิกเข้าทางเดียว** สมมติฐานที่ไม่มีใครตั้งคำถามคือ **"จุดคือประสบการณ์ของผู้ใช้"** มันจึงรอคุณพิมพ์
  ทั้งที่ Evidence Agent ค้นโลกจริงทุกครั้งแล้วทิ้งสิ่งที่เจอ · คลังยังเป็นของคุณ (ทุกจุดติดป้ายที่มา และยับยั้งได้ถาวร)
  แต่คุณไม่ต้องเป็นคนเดียวที่แบกความรู้เข้ามาอีกต่อไป

- **06.8 — "ผ่านทุกด่าน" เลิกเป็นคำตัดสินสุดท้าย** ทุกด่านที่ระบบมีตัดสินที่วินาทีที่โค้ดเขียนเสร็จ
  จึงพิสูจน์ได้แค่ว่า **"ทำได้"** ไม่มีด่านไหนถามว่า **"มีใครใช้"** ทั้งที่คำตอบนอนอยู่ใน `endpoint-usage.json`
  มาตั้งแต่ 06.6 — แต่ถูกใช้เป็นแค่ใบอนุญาตให้ถอดเส้นทาง ระบบจึงสะสมของที่ถูกเรียก 0 ครั้งได้ไม่จำกัด
  และนับทุกครั้งว่าเป็นความคืบหน้า · ตอนนี้ทุกรอบต้องประกาศเส้นทางที่มันจะถูกใช้ผ่าน แล้วอีกไม่กี่วัน
  บันทึกการใช้งานให้คะแนนมันด้วยสูตรเดียวกับที่ให้คะแนนไอเดียของคุณ — และคะแนนนั้นเปลี่ยนว่าจะสร้างอะไรต่อ
- **08 — คลังเลิกโตทางเดียว** 06.6 หากำแพง "ความคืบหน้าแปลว่าใหญ่ขึ้น" เจอในฝั่งโค้ดแล้วทำลายมัน
  แต่กำแพงรูปทรงเดียวกันฝั่งความรู้ยืนอยู่ครบโดยไม่มีใครมอง: ทุกทางเข้าเพิ่มจุด ทางออกมีแค่นิ้วมือมนุษย์
  และ "การลืม" ของระบบเป็นแค่ป้ายสี — จุดที่ถูกทำเครื่องหมายว่าถูกลืม ยังถูกอ่านครบทุกตัวอักษรทุกรอบ
  · ตอนนี้พรอมป์ตมีเพดาน (ลืมเนื้อหาได้จริงโดยไม่ลืมการมีอยู่) และคลังยุบรวมตัวเองได้โดยพิสูจน์ได้ว่าไม่มีอะไรหาย

**คลังที่โตได้เฉพาะตอนเจ้าของว่าง คือคลังที่หยุดโตเป็นส่วนใหญ่ของเวลา —
และคลังที่โตได้อย่างเดียว คือคลังที่วันหนึ่งจะใหญ่เกินกว่าที่ตัวมันเองจะอ่านจบ**

**และระบบที่ตัดสินตัวเองเสร็จภายในวันเดียวกับที่เขียนโค้ด คือระบบที่พิสูจน์ได้เสมอว่า "ทำได้"
โดยไม่เคยต้องรู้เลยว่ามีใครใช้ — ความคืบหน้าที่วัดจากด้านผู้สร้างล้วน ๆ ก็แยกไม่ออกจากการสะสมของที่ไม่มีใครแตะ**
